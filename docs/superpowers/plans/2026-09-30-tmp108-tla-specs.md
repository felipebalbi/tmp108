## Task 1 — `Tmp108Codec.tla` + `.cfg`

Pure arithmetic, no variables, no `Next`. Checked as constant
expressions so it costs milliseconds.

Operators:

- `RegToCelsius(w)` — arithmetic shift right by 4 with sign extension,
  mirroring `Celsius::from_register` (`src/lib.rs:426-431`).
- `CelsiusToReg(c)` — shift left by 4, mirroring `to_register`
  (`src/lib.rs:437-439`).
- `WriteMaskLimit(w)` — clears bits 3:0, modelling measurement E6.
- `ConfigToWord` / `WordToConfig` — the 16-bit codec including `cr` and
  `id`, bit positions from `tmp108.ddsl:24-79`.
- `ApplyConfig(w, cfg)` — mirroring `ops::apply_config`
  (`src/lib.rs:562-579`), including the `0b01 -> 0b00` normalisation and
  the deliberate non-canonicalisation of `0b11`.

Properties, all over the **full** domain:

- `RoundTripsCelsius` — `RegToCelsius(CelsiusToReg(c)) = c` for all 4096.
- `DecodeIsTotal` — all 65,536 words land in `-2048..2047`.
- `MonotonicDecode` — `w1 <= w2 => RegToCelsius(w1) <= RegToCelsius(w2)`
  over signed interpretation. **This is the assumption the degrees
  abstraction rests on**; checking it here is what makes the seam sound.
- `LimitNibbleReadOnly` — `RegToCelsius(WriteMaskLimit(w)) =
  RegToCelsius(w)`. Finding 2: the nibble is unwritable *and*
  irrelevant to the threshold.
- `ApplyConfigPreservesUnmodelled` — the `0x4F98` preserved mask.
- `ApplyConfigNormalisesOnlyOneShot` — `00->00, 01->00, 10->10, 11->11`.

**Verify:** `python scripts/check-tla.py --only Tmp108Codec` passes.

## Task 2 — `Tmp108Hw.tla` + `Tmp108Hw.cfg`

The chip alone. `CONSTANTS MinTemp, MaxTemp, PorConfig, PorTLow,
PorTHigh`.

Actions: `Drift`, `StartConversion`, `FinishConversion`,
`ReadRegister(r)`, `WriteRegister(r, v)`, `GeneralCallReset`.

Care points:

1. `FinishConversion` sets `mode' = 0` when `mode = 1`
   (`datasheet.txt:746`) and bumps `convEpoch`.
2. A write of `mode := 0` during `converting` does **not** cancel the
   conversion (`datasheet.txt:741`). This is why `converting` is an
   explicit variable.
3. `ReadRegister("Config")` clears `fl`, `fh` and `intAlert`
   (`datasheet.txt:926`, E4). Reads of other registers clear nothing
   (E2).
4. `WriteRegister("Config", v)` ignores the `fl`/`fh` bits (E1).
5. Comparator latch: assert on `tempReg > thigh \/ tempReg < tlow`;
   deassert only on `tlow + hys <= tempReg <= thigh - hys`
   (`datasheet.txt:980-985`, E5).

Invariants per the spec's table. `OneShotSelfClears` is a leads-to and
needs weak fairness on `FinishConversion`.

**Verify:** `--only Tmp108Hw` passes; deliberately break the comparator
band and confirm `ComparatorQuiescent` catches it, then revert.

## Task 3 — `Tmp108Driver.tla` + `Tmp108Driver.cfg`

`EXTENDS Tmp108Hw`. Build incrementally and keep the gate green at each
step:

1. `Idle` plus the single-transaction operations: `probe`,
   `read_configuration`, `temperature`, `set_low_limit`,
   `set_high_limit`. Add `DriverTypeOK`.
2. The read-modify-write operations: `configure`, `shutdown`. Bus-error
   branching becomes meaningful here — a failed write after a successful
   read.
3. `one_shot` as its step machine: prepare, settle, check, trigger,
   poll ×8, read. Add `NoStaleOneShot` and the `triggerEpoch` capture.
   Mirror `expected_one_shot_timeline` (`src/lib.rs:4313-4335`),
   including the redundant second read of `0x01`.
4. `continuous` with entry, an abstract closure body, and cleanup. Add
   `ContinuousOkImpliesShutdown`.
5. `Cancel`. Add `CancelledContinuousLeaks`.
6. `wait_for_alert` with the full retention machine
   (`src/lib.rs:1594-1699`): retained branch, comparator arms, interrupt
   fast path, interrupt slow path, arm-before-T, clear-after-T. Add
   `NoLostAcknowledgedAlert` and `AtMostOneObligation`.

**Verify after each sub-step:** `--only Tmp108Driver` passes and the
distinct-state count stays within budget.

## Task 5 — `scripts/check-tla.py`

Per the spec's runner section. Build the manifest, jar resolution,
subprocess invocation, output parsing, reporting and exit code.

**Verify:**
- `--list` prints the manifest.
- A deliberately corrupted `.cfg` produces a clear failure, not a
  traceback.
- Removing the jar produces the one-line guidance message.
- `--only` and `--deep` behave.
- Exit code is 0 on success, 1 on any mismatch.
